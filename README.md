# 耳机电量记录 App（BTBatteryLogger）

测试用蓝牙耳机电量记录工具。通过 **BLE GATT 直读 `0x180F / 0x2A19`** 获取耳机电量，
常驻通知实时显示，画曲线，导 CSV 给报告用。

---

## 一、它解决什么

- 测试时放歌 / 通话，持续记录电量变化
- 常驻通知实时显示当前电量
- 导出 CSV，带场景分组统计，可直接贴进测试报告
- **自动判断固件上报粒度**：是 1% 还是 10 档，采几十个点就看出来

## 二、精度说明（重要）

**精度不由 App 决定，由耳机固件的 SOC 算法决定。**

本 App 走的是：

```
耳机固件 SOC 计算（决定精度）
    ↓
BLE GATT 0x2A19 (uint8, 0-100)
    ↓
App 原值读取，不做四舍五入、不平滑、不插值
    ↓
界面显示 + CSV 记录
```

实测该设备暴露了 `0x2A19`，`Properties: NOTIFY, READ`，所以：
- App 不用轮询，电量变化耳机主动推
- 值就是固件算出来的原始值，采一段后界面会告诉你真实粒度

**粒度检测逻辑**：
- 只出现 11 个不同值（0,10,...,100）→ 固件只报整十
- 出现几十个不同值，最小间隔 1 → 真 1% 粒度

## 三、设备实测情况

| 项目 | 结果 |
|---|---|
| BLE 广播 | ✅ 有 |
| Battery Service `0x180F` | ✅ 有 |
| Battery Level `0x2A19` | ✅ 有，NOTIFY + READ |
| CCCD `0x2902` | ✅ 有 |
| 私有电量特征 | ✅ 有（`13bb0001-5884-4c5d-b75b-8768de...`，值形如 `3D 00` = 61） |

私有特征值 `3D 00` 是 uint16 小端 = 61，和标准 `0x2A19` 的 60% 相差 1。
说明固件端有「原始值」和「平滑后值」两套。**App 两个都读，CSV 里标来源**，
方便你判断哪个更接近真值。

## 四、构建

需要 Android Studio（Hedgehog 或更新）+ JDK 17 + Android SDK 34。

```
1. Android Studio → Open → 选 BTBatteryLogger 目录
2. 等 Gradle sync 完成
3. 手机开 USB 调试，连上去
4. Run 'app'
```

最低支持 Android 8.0（API 26）。
需要的权限：`BLUETOOTH_SCAN`、`BLUETOOTH_CONNECT`（Android 12+）、
`POST_NOTIFICATIONS`（Android 13+）、`ACCESS_FINE_LOCATION`（Android 11 及以下）。
App 会自己申请。

## 五、怎么用

1. **先在系统蓝牙里「取消保存」耳机**（重要！BLE 被系统占用时扫不到）
2. 打开 App → 点右上「扫描」→ 选目标设备（会显示 MAC + 信号强度）
3. 耳机放桌上，距离手机 30cm 内
4. 选场景：待机 / 放歌 / 通话（切场景时点一下，CSV 会记）
5. 调兜底轮询间隔（默认 60 秒）
6. 点「开始记录」→ 通知栏出现常驻电量
7. 让它跑，该放歌放歌，该通话通话
8. 结束点「导出 CSV」

### 关于「私有UUID」按钮

nRF Connect 里看到的私有特征 UUID 如果完整，填进去 App 会同时读它，
CSV 里会区分来源。留空则只读标准 `0x2A19`。

需要填完整的 36 位 UUID，例如：
```
13bb0001-5884-4c5d-b75b-8768de??????
```
（`???` 部分要你从 nRF Connect 完整复制，屏幕上是省略号）

## 六、CSV 长这样

```csv
# 蓝牙耳机电量记录（BLE GATT 0x2A19）
# 设备MAC,41:42:49:FA:18:06
# 开始时间,2026-11-07 18:00:00
# 兜底轮询间隔(ms),60000
# 采样点数,180
# 出现过的不同电量值个数,37（若为 11 说明固件只报 10 档；若几十个说明 1% 粒度）

# ===== 场景汇总 =====
场景,起始电量,结束电量,消耗,时长(分钟),掉电速率(%/h),采样数
待机,100,95,5,59.0,5.08,60
放歌,90,72,18,59.0,18.31,60
通话,72,55,17,30.0,34.00,60

# ===== 原始采样 =====
时间,时间戳(ms),电量(%),原始值有效,场景
2026-11-07 18:00:00.123,1762500000123,100,1,放歌(推送)
2026-11-07 18:00:30.456,1762500030456,99,1,放歌(推送)
```

**场景汇总那段是给报告用的**，直接看哪个场景最耗电。

## 七、后台被杀怎么办

Android 对后台服务管得严，长时间测试（几小时）建议：

**设置 → 应用 → 耳机电量记录 → 电池 → 选择「无限制」**

各家 ROM 还有自己的省电策略（小米、华为、OPPO 等），需要在系统管家里也放行。

## 八、已知限制

1. **BLE 扫不到设备**：最常见原因是耳机已被系统蓝牙连接（BLE 被占用）。
   先在系统里「取消保存」，再扫描。
2. **私有 UUID 不够完整**：nRF Connect 屏幕上显示省略号，需要点进去复制完整值。
   不填也能用，只是少一路数据源。
3. **Android 12 以下的 HFP 兜底是反射调用**，某些机型可能失败。
4. **Doze 状态下轮询会被延迟**。但 BLE 通知是真推送，不受影响，
   所以只要耳机在推，数据就不会断。
5. **左右耳/充电盒独立电量没做**：标准 `0x2A19` 只有一个值。
   如果要做，得靠私有特征的扩展字段，需要固件提供协议说明。

## 九、文件说明

```
app/src/main/java/com/istar/btbattery/
├── MainActivity.java      主界面：扫描选设备、显示、控制、导出
├── MonitorService.java    前台服务：BLE 连接、记录、通知、写 CSV
├── BleBatteryReader.java  BLE GATT 读 0x2A19（主通道，Read+Notify）
├── BatteryReader.java     HFP 读电量（BLE 失败时兜底）
├── BatteryLog.java        采样存储 + CSV 生成 + 粒度统计 + 场景分组
└── ChartView.java         电量曲线自绘
```

## 十、验证清单（装好后按这个走）

- [ ] 装 App，授权蓝牙和通知
- [ ] 系统蓝牙里取消保存耳机
- [ ] App 点「扫描」，能扫到设备并显示 MAC
- [ ] 点「开始记录」，通知栏出现电量
- [ ] 界面「连接状态」显示「已订阅电量通知」
- [ ] 「BLE 读数」开始增长
- [ ] 放歌 10 分钟，看曲线有没有变化
- [ ] 导出 CSV，用 Excel 打开看场景汇总
- [ ] 重点看「上报粒度检测」那行结论

**如果「连接状态」一直停在「扫描中…」**，说明耳机被系统占用或不在范围。
**如果显示「错误：该设备没有 0x180F 电池服务」**，说明固件的服务表变了。
